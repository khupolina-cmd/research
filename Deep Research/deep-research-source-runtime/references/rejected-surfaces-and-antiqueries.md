# Rejected Surfaces And Anti-Queries

This file is a hard runtime exclusion layer for the Deep Research project.

These exclusions beat nearby convenience.
If a rejected surface is easy to find or seems superficially relevant, that does not make it eligible again.

If a surface, family, or query class is listed here, do not casually reintroduce it through:

- a resource shortlist;
- a maybe-list;
- a priority summary;
- a hidden gems block;
- a prompt example;
- a “broad options” paragraph.
- a change of output object such as “I know they asked for sites, but this campaign page is useful”.

## Rejected surfaces

### Screen / UI / UX libraries
- Typewolf
- Mobbin
- Refero
- Page Flows
- Screenlane
- ScreensDesign / Scrnshts

Why rejected:
- wrong object class for the current work;
- drift into UI/UX screens instead of text modules or product+text compositions;
- often gated and practically useless for the user’s task.

### Noisy aggregators / weak-fit editorial identity surfaces
- Muzli
- Brand New / UnderConsideration

Why rejected:
- too aggregator-like or commentary-led;
- weak repeated-hunting value for the user’s current tasks.

### Institutional / archive-heavy / stylistically dead for this project
- Letterform Archive Online Archive
- Dinamo Typefaces
- Poster House / museum collections
- AIGA Design Archives
- Library of Congress WPA Posters
- Hoover Institution Poster Collection
- MoMA design/poster collection trails
- CalArts Poster Archive
- People’s Graphic Design Archive
- IADDB
- Second Hand / Vernacular Cover Archive

Why rejected:
- too archival, canonical, slow, or friction-heavy for the live style-first workflow;
- not enough practical hit-rate for the current reference-hunting goals.

### Broken / wrong-path / low-fit commercial references
- Vogue Archive
- Ads of the World
- The Impression — Fashion Ad Campaigns
- Models.com — Campaigns
- AdForum Creative Library

Why rejected:
- wrong direction, weak practical fit, too much clutter, or broken/poor utility.

### Cinema / movie-poster drift
- IMP Awards
- MUBI Notebook — Movie Poster of the Week
- CineMaterial / MoviePosterDB

Why rejected:
- wrong object class;
- cinema key art is not the same search field as product/object commercial text+photo.

### Utility tools instead of reference surfaces
- Typopo
- Whitespaces / Whitespaces+ by Kirill Belyaev

Why rejected:
- useful tools in the abstract, but completely wrong output type for this project;
- they are not visual reference surfaces.

### Template / prompt marketplaces masquerading as stylish references
- PicX Studio template pages
- PSD / prompt / AI mock-generator landing pages
- template-first "luxury skincare commercial photography" pages

Why rejected:
- they imitate the syntax of the target object while failing the authorship, quality, and current-style test;
- they are a direct source of cheap, template-like, pseudo-premium collage aesthetics;
- they produce anti-examples that can contaminate naming and retrieval.

## Anti-query patterns

### 1. UI flow libraries / app screen databases / UX pattern sites
Reject because:
- they return screens, flows, and product patterns instead of typographic fragments or poster-like devices.

### 2. Museum / institutional poster collections
Reject because:
- they lead to canonical, historical, often stylistically dead corpora for this project.

### 3. Movie poster databases / cinema key art archives
Reject because:
- they push the search into the wrong object class.

### 4. Fashion campaign databases without explicit product-object + type proof
Reject because:
- they are often image-first and miss the needed typography-in-frame logic.

### 5. Generic mass ad archives / creative libraries
Reject because:
- they produce clutter and directory logic rather than tightly useful signal.

### 6. Microtypography utilities / whitespace tools
Reject because:
- they are production helpers, not visual reference surfaces.

### 7. Archive-first oddities without current practical utility
Reject because:
- they may be interesting, but they consume time without serving the current output object.

### 8. Generic platform search pages as fake deliverables
Reject because:
- they masquerade as operational answers while pushing the user back into open-ended self-search;
- they do not satisfy requests for direct studios, agencies, accounts, or validated resource links.

### 9. Template / prompt marketplaces that mimic the brief
Reject because:
- they look superficially on-brief while being the exact anti-example the user wants to exclude;
- they are often synthetic, template-first, or prompt-sludge-adjacent rather than real authored commercial work.

## Runtime rule

If one of these surfaces appears again in your own draft prompt or recommendation, treat it as a failure signal.

Before sending a final prompt, quickly scan for:

- rejected names;
- rejected query classes;
- softened reintroductions like “maybe,” “situational,” or “worth checking”.
